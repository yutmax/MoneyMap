# Система стилей

Документ объясняет, как в MoneyMap устроены стили и почему именно так. Он важен не меньше кода: без него система развалится на третьем разработчике (или на самом себе через полгода).

## Структура

```
apps/web/src/styles/
  _functions.scss     rem(), em(), fluid()
  _breakpoints.scss   карта брейкпоинтов, from(), until(), between(), hover(), reduced-motion()
  _mixins.scss        focus-ring, surface, container, tabular-numbers, transition, auto-grid, …
  _tokens.scss        CSS-переменные: цвета, шкалы, радиусы, тайминги
  _reset.scss         глобальное обнуление
  _base.scss          базовые стили элементов
  _utilities.scss     .visually-hidden, .container
  _layers.scss        порядок слоёв каскада
  _index.scss         фасад, подмешиваемый в каждый модуль
  global.scss         единственная точка входа, импортируется в main.tsx
```

Два уровня, и граница между ними жёсткая:

- **Глобальный слой** — `global.scss`, подключается один раз в `main.tsx`. Сюда входит только то, что по определению не принадлежит ни одному компоненту: обнуление, токены, типографика тега `body`, две утилиты.
- **Стили компонентов** — `*.module.scss` рядом со своим `.tsx`. Больше ничего глобального в проекте не появляется.

## Автоматический импорт фасада

`vite.config.ts` подмешивает `@use "index" as *;` в начало каждого `.scss`, который обрабатывает:

```ts
scss: {
  api: 'modern-compiler',
  additionalData: '@use "index" as *;\n',
  loadPaths: [stylesPath],
}
```

Поэтому в модуле можно сразу писать `rem(16)`, `@include focus-ring`, `@include from("md")` без относительных путей, которые ломаются при переносе компонента в другую папку.

**Важное ограничение:** `_index.scss` форвардит только функции, брейкпоинты и миксины — то, что не печатает ни одного байта CSS. Если туда попадёт `_tokens.scss` или `_reset.scss`, их содержимое продублируется в каждом из ~15 модулей проекта.

## fluid() вместо adaptiveValue

В прототипе был миксин `adaptiveValue` из шаблона FLS. Он считал правильно — это линейная интерполяция через `clamp()`, — но каждый его вызов печатал **три** media-запроса:

```css
/* @include adaptiveValue("font-size", 35, 25) */
@media (min-width: 120em) {
  font-size: 2.1875rem;
}
@media (min-width: 20em) and (max-width: 120em) {
  font-size: clamp(1.5625rem, …, 2.1875rem);
}
@media (max-width: 20em) {
  font-size: 1.5625rem;
}
```

Два из трёх избыточны: `clamp()` зажимает значение между границами сам — в этом его смысл. Media-запросы нужны были только ради параметра `$keepSize` и ради закомментированного `@supports`-фоллбэка для браузеров без `clamp()`, которых в 2026 году не осталось.

Здесь то же самое делает функция:

```scss
@function fluid($max, $min, $width-max: 1440, $width-min: 390) { … }
```

```scss
font-size: fluid(35, 25);
/* → clamp(1.5625rem, 1.3768rem + .7619vw, 2.0625rem) — одна строка, ноль media-запросов */
```

Функция лучше миксина не только размером вывода:

- её можно положить в `var()`, и именно так собрана шкала токенов;
- её можно использовать в сокращённом свойстве: `padding: fluid(40, 24) fluid(24, 16)`;
- её можно подставить внутрь `calc()`.

Наклон задаётся в `vw`, смещение — в `rem`. Это не стилистика: чистый `vw` игнорировал бы увеличенный размер шрифта в настройках браузера, чистый `rem` не был бы текучим.

Для сравнения: 25 вызовов `fluid()` в токенах дали бы 75 media-запросов на старом миксине. В собранном CSS их **28 на всё приложение**, и это `prefers-color-scheme`, `prefers-reduced-motion`, `any-hover` и настоящие брейкпоинты.

## Шкала вместо магических числ

Главная проблема `adaptiveValue` была не технической, а дисциплинарной: он поощрял писать размеры на месте вызова. В прототипе на одном экране входа жило восемь несвязанных чисел.

Поэтому размеры объявлены один раз шкалой:

```scss
--step--2 … --step-4      /* типографика, 7 ступеней */
--space-3xs … --space-2xl /* отступы, 8 ступеней */
```

В компонентах — только `var(--step-1)` и `var(--space-m)`. Исключения (`rem(34)` для нестандартной высоты кнопки) есть, но они на то и исключения.

## Токены в CSS-переменных, а не в Sass

`$green` из прототипа компилируется в конкретный цвет и переключить тему уже не может. Поэтому всё, что может меняться в рантайме, — CSS-переменные.

В Sass остаётся только то, что принципиально не умеет жить в рантайме:

- **брейкпоинты** — media-запрос не читает `var()`;
- **математика** — `fluid()`, `rem()`;
- **миксины**.

Тёмная тема — по умолчанию (перенесена из прототипа), светлая — миксином `light-theme`, который применяется дважды:

```scss
@media (prefers-color-scheme: light) {
  :root:not([data-theme='dark']) {
    @include light-theme;
  } /* системная настройка */
}
:root[data-theme='light'] {
  @include light-theme;
} /* явный выбор сильнее */
```

Атрибут `data-theme` ставится инлайн-скриптом в `index.html` до первой отрисовки — иначе видна вспышка чужой темы между загрузкой CSS и монтированием React.

Производные цвета считаются через `color-mix(in oklab, …)`, а не Sass-функциями `darken()`/`lighten()` (которые вдобавок устарели): одна формула работает в обеих темах, потому что считается в рантайме.

## Cascade layers

```scss
@layer reset, tokens, base, utilities;
```

Стили компонентов **сознательно вне слоёв**: любой неслоёный стиль сильнее любого слоя. Поэтому компонент всегда выигрывает у обнуления и базовых стилей без повышения специфичности — ровно та проблема, из-за которой в прототипе приходилось писать `.login-input:focus` вместо `:focus`.

Порядок слоёв объявлен в `_layers.scss`, и этот файл подключается первым: позиция слоя фиксируется в месте первого упоминания имени.

## Брейкпоинты

Диапазонный синтаксис Media Queries 4 вместо `min-width`/`max-width`:

```scss
@include from("md") { … }   // @media (width >= 48rem)
@include until("md") { … }  // @media (width < 48rem)
```

Этим снимается старая проблема стыка: с `min-width`/`max-width` приходилось писать `767.98px`, чтобы правила не перекрывались на одном пикселе. `>=` и `<` не пересекаются по определению.

Значения — в `rem`, а не в `px`: иначе человек с увеличенным базовым шрифтом получал бы десктопную вёрстку на телефоне.

Там, где количество элементов заранее неизвестно, брейкпоинтов нет вообще — сетка решает сама:

```scss
@include auto-grid(rem(260)); // repeat(auto-fill, minmax(min(260px, 100%), 1fr))
```

## Правила, которые стоит соблюдать

1. **Никакого `transition: all`.** Только `@include transition(background-color, color)` — миксин перечисляет свойства и сам уважает `prefers-reduced-motion`.
2. **`:focus-visible`, а не `:focus`** — кроме текстовых полей, где подсветка границы ожидаема и от клика мышью. В прототипе кнопки перекрашивались после обычного клика и оставались в этом состоянии.
3. **`@include hover`, а не `&:hover`.** Миксин оборачивает в `@media (any-hover: hover)`: без этого `:hover` на тач-устройстве залипает после тапа.
4. **Внутри модуля БЭМ не нужен.** `.root`, `.title`, `.item` — имена и так становятся уникальными после компиляции. `.login-form__pass-label` был вынужденной мерой глобального CSS.
5. **Суммы — только с `@include tabular-numbers`.** С пропорциональными цифрами разряды в колонке не выравниваются.
6. **Логические свойства** — `margin-block`, `padding-inline`, `inset-inline-end`: чтобы добавление RTL-локали не превратилось в ревизию всех отступов.

## Что получилось по размеру

Собранный CSS всего приложения — **18.8 КБ (4.5 КБ gzip)**: обнуление, токены двух тем, базовая типографика и стили двенадцати компонентов. В прототипе один каталог `scss/libs/` занимал 219 КБ исходников.
